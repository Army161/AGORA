Your second agent has no idea what the first one just did.

Open Claude Code and Claude Desktop side by side and you have two capable agents that cannot see each other. Both pick up the same task. Both edit the same file. Neither knows. Agora gives them a room — one shared workspace where work is claimed, files are locked, and every action is written to a log they all read.

Why this isn't a model problem

A stronger model doesn't stop two agents writing to the same file at the same time — it just does it more confidently. Coordination is a state problem: it needs somewhere outside both agents that records who owns what. Today no such place exists, so the human becomes the message bus.

⚠

Duplicated work

Two agents independently solve the same problem because neither knows the other started.

✕

Clobbered edits

Concurrent writes to the same file, with no lock and no protocol for who owns what.

↯

Lost context

Handoffs happen by pasting a wall of text into another chat, losing provenance and history.

Humans solved this a long time ago, and not with intelligence — with boards, tickets, check-outs and handover docs. Cheap external state anyone can read to find out who owns what. Agora is those primitives, rebuilt with machine-native semantics: claims that expire on their own, because agents never notice a stale ticket.

The moment it matters

Two agents, one task, no human refereeing. This is the whole product in five calls.

WhoCallWhat happens
Codeagora_add_taskT-0001 lands in the shared pool, visible to everyone.
Codeagora_claim_taskLeased to Code for 30 minutes. Status in_progress.
Desktopagora_claim_taskRefused — “owned by Code until 14:32”. Desktop is told why, and goes elsewhere.
Codeagora_create_handoffWrites handoffs/H-0001.md with context, artifacts and next steps.
Desktopagora_ack_handoffDesktop now owns it. The transfer is in the log, with timestamps.

That refusal is the product. Without it, Desktop silently starts the same work and one of them overwrites the other. With it, the second agent gets a specific answer — who holds it, and until when — and adapts. No human had to notice.

And if Code crashes holding the lease?

Nothing breaks. The lease expires and T-0001 returns to the pool automatically, claimable by anyone without a force flag. Ownership in Agora always has an expiry, because agents don't file a handover on their way out — they crash, get closed mid-task, or quietly stop.

How it works

One MCP server, one workspace folder. Every surface that points at the same folder is in the same room — that is the entire trick. State lives on disk, not in any single agent's context window.

Quick start

The engine is pure Python standard library, so there is nothing to compile and no service to host for local use.

bash · macOS / Linux 
# 1. get it
git clone https://github.com/Army161/AGORA.git && cd AGORA
pip install -r server/requirements.txt

# 2. run the server against a shared workspace folder
python server/agora_mcp.py --workspace ~/.agora/main

Then point every surface at that same --workspace path. The first agora_join call bootstraps the folder. Full per-OS and per-surface instructions are on the install page.

Two gotchas worth knowing up front. agora_join takes agent_id (not name), and agora_post_update takes message (not summary). Both are easy to get wrong from memory.

What you get

Nineteen tools, grouped into five primitives. Every one of them writes to the shared event log, so the room always has a complete history of who did what.

Presence

join · board · events

Announce yourself, read the room, and poll incrementally from the last sequence number you saw.

Tasks with leases

add_task · claim_task · update_task · release_task

A claim is a lease with a TTL. If an agent crashes mid-task, the lease expires and the work returns to the pool automatically.

Resource locks

lock_resource · unlock_resource

Claim the file you are about to edit so a second surface does not overwrite you. Also lease-backed, so locks cannot leak.

Handoffs

create_handoff · list_handoffs · ack_handoff · complete_handoff

Structured transfer of work with summary, context, artifacts and next steps — written to a durable markdown doc, not pasted into a chat.

Messaging & updates

send_message · get_messages · post_update

Direct or broadcast notes between agents, plus a human-readable progress feed.

Shared memory

pin_fact · set_house_style · get_memory

Pin facts every agent reads before acting, and set one house style so output stays consistent across surfaces.

Concurrency is tested, not assumed

The suite fires eight threads at a single unclaimed task and asserts that exactly one wins and seven are refused. A second test hammers the event log from four threads and asserts no sequence number is ever duplicated. Both run on Ubuntu, macOS and Windows against Python 3.10 and 3.12 — so the file-locking behaviour is proven on NTFS, APFS and ext4 rather than mocked.

It refuses to be insecure by accident

In HTTP mode the server will not start if you bind a non-loopback interface without a bearer token — the common way a local tool gets accidentally published to a network. Tokens are compared with hmac.compare_digest, so the check is not timing-attackable.

server/agora_mcp.py 
if token is None and not _is_loopback(args.host):
    ap.error(f"refusing to bind {args.host} without a token. "
             "Set AGORA_TOKEN (or --token) before exposing beyond localhost, "
             "or bind --host 127.0.0.1 for local-only use.")

Failure model. Every claim and lock is a lease with an expiry, so the worst case of an agent dying mid-task is a delay bounded by the TTL — never a permanently wedged room.
